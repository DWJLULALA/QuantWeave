# 抖音文案与开场 hook

主张：**先看市场阶段，再看选股排名。** 技术内容负责解释为什么，真实操作负责证明工作台能检查这些判断，AI 安装入口负责让感兴趣的人继续体验。

## 主推版本：排名很准，为什么还亏

**标题**：RankIC 很高，为什么账户还在亏？

**封面大字**：股票排得准，为什么还亏？

**前 4 秒旁白**：股票排得很准，账户为什么还在亏？

**第一转折**：因为排第一，也可能只是跌得最少。

**发布文案**：

> 排第一，也可能只是跌得最少。RankIC 看的是相对排序，市场方向还要单独判断。
>
> 我把研究拆成三层：升浪与缠论看市场阶段，Kronos 的近期 LoRA 适配 + EMA 做排名，再用 SET10 补充反转、震荡风格。数据来源、回放和日志都放进同一个工作台。
>
> QuantWeave 已开源。把 GitHub 链接和 README_AGENT.md 发给能操作终端的 AI，让它帮你启动本地 demo。无需 GPU、行情账号或模型权重。
>
> 项目：github.com/DWJLULALA/QuantWeave
> 研究与工具展示，不构成投资建议。
>
> #量化研究 #开源项目 #AI工具 #Python #因子研究

**置顶评论草稿**：

> 安装入口在 GitHub 的 README_AGENT.md。复制这句给 AI：“请按 README_AGENT.md 安装 QuantWeave 本地 demo，运行测试、验证服务，然后给我访问地址和重启方法。”Demo 是冻结样例；真实数据与模型环境需另外配置。

## 可替换的开场

| 方向 | 前 3–5 秒 | 接下来的画面 / 句子 |
|---|---|---|
| 认知冲突（主推） | 股票排得很准，账户为什么还在亏？ | 排名 1/2/3 分别 −1%/−3%/−5%；标注“机制示意，非回测” |
| 安装入口 | 我把这套量化工作台开源了，安装说明是写给 AI 的。 | GitHub + README_AGENT.md；“先启动本地 demo，再看这三层逻辑” |
| 因子互补 | 一个因子擅长趋势，行情突然反转怎么办？ | Kronos 与 SET10 两列；以注明日期的 IC 对照解释风格差异 |
| 研究顺序 | 选股之前，我先问一个问题：现在是什么行情？ | 大盘 → 行业 → 个股；上涨 / 下跌 / 盘整 |
| 技术切入 | 给时序模型做微调，为什么我还要加第二种因子？ | LoRA → 排名 → EMA → SET10；同时解释平滑的滞后 |

备用标题：

- 《量化选股前，我先判断这三件事》
- 《Kronos + SET10：行情换挡，因子也要有不同风格》
- 《把 GitHub 链接发给 AI，这个量化 Demo 就能开始安装》

## 竖屏成片的节奏

| 时间 | 内容 | 作用 |
|---|---|---|
| 0–4 秒 | 排名准却亏钱的提问 | 明确冲突 |
| 4–11 秒 | “第一名也可能是负收益” | 用三个数字解释原因 |
| 11–19 秒 | 结构 → Kronos/LoRA/EMA → SET10 | 保留技术识别度 |
| 19–29 秒 | GitHub + 智能体 README | 给出可执行的体验入口 |

竖屏版为独立排版，未直接裁切横屏图表；完整技术解释在横屏版。完整片中的实验数字只按指定日期的短窗口研究记录表述，原始预测尚未重新核算。

## 比较不同 hook 的办法

先用同一主体与结尾，仅替换前 4 秒和封面，比较开头留存、完播和安装文档访问。主推“排名准却亏钱”用于吸引研究问题明确的人；“安装交给 AI”用于突出开源工具的低体验门槛。不要把播放量差异直接归因于 hook，发布时间与受众也会影响结果。

不使用“稳赢”“每天自动赚钱”“固定对冲”“收益提升 39 倍”等现有证据不支持的说法。以上是可编辑的发布草稿，本次没有代发抖音或评论。
